# 26 - Go-To-Market Lanzamiento V1 Directo Y Primeros Usuarios

**Estado:** V1.1 - Estrategia de lanzamiento V1 directo, sin beta como etapa de producto  
**Ultima actualizacion:** 3 de junio, 2026  
**Depende de:** `01_user_personas.md`, `02_nombre_producto.md`, `03_analisis_competitivo.md`, `04_tam_sam_som.md`, Fase 2 Alcance V1, Fase 3 Producto, `24_privacidad_proteccion_datos.md`, `25_unit_economics_costos.md`

---

## 1. Decision

Manzana no lanzara una beta recortada como etapa principal.

Decision:

```text
Construir por cortes internos.
Lanzar al usuario una V1 completa, cuidada y coherente.
```

La V1 directa no significa lanzar sin control. Significa que el producto visible al usuario debe ser el producto V1 completo, no una version inferior llamada beta.

Regla:

> No se usa "beta" como promesa, etiqueta, etapa publica ni justificacion para bajar calidad.

---

## 2. Que Significa GTM En Manzana

GTM no significa hacer una version menor.

GTM significa decidir:

- a que usuarios se lanza primero;
- que promesa se comunica;
- que canales se usan;
- que condiciones deben cumplirse antes de abrir;
- como se mide si Manzana realmente crea valor;
- como se evita atraer usuarios equivocados;
- como se aprende sin romper confianza.

La pregunta central:

```text
Como llevamos Manzana V1 al mercado sin diluir calidad, confianza ni claridad?
```

---

## 3. Principios No Negociables

| Principio | Regla |
|---|---|
| V1 completa visible | El usuario no recibe una version recortada como producto principal. |
| Calidad antes que volumen | No abrir mas usuarios si la experiencia no se sostiene. |
| Cortes internos, no versiones publicas | Los cortes de implementacion ordenan construccion; no son releases de usuario. |
| WhatsApp primero | La entrada principal debe ser conversacional; Dashboard complementa. |
| Una promesa clara | No vender todas las features; comunicar el dolor principal por segmento. |
| Sin culpa | El marketing no debe avergonzar al usuario por su dinero. |
| Sin promesas financieras falsas | No prometer ahorro garantizado, inversion, credito ni asesoria financiera. |
| Privacidad visible | El usuario debe entender que Manzana maneja datos sensibles con cuidado. |
| Consentimiento real | No meter usuarios a flujos proactivos sin opt-in claro. |
| Medicion desde el primer dia | Cada usuario debe tener fuente, activacion, uso, friccion, costo y feedback medidos. |

---

## 4. Que No Es El GTM De Manzana

No es:

- lanzar una beta incompleta;
- publicar anuncios genericos de "controla tus finanzas";
- competir como app de presupuesto tradicional;
- empujar descarga de app antes de mostrar valor;
- buscar viralidad sacrificando confianza;
- vender "IA financiera" sin explicar para que sirve;
- prometer que la app "hace todo automaticamente";
- forzar Gmail en el primer minuto;
- hablar de dashboards antes de demostrar captura facil;
- abrir al publico sin soporte, legal operativo, costos y privacidad listos;
- medir exito solo por registros.

Regla:

```text
Registro sin uso no es traccion.
Uso con claridad y retorno si lo es.
```

---

## 5. Producto Que Se Lanza

Manzana V1 debe lanzarse como una experiencia completa inicial:

- WhatsApp para registrar, corregir, confirmar y conversar.
- Dashboard para revisar, entender, corregir y ver contexto.
- Movimientos, cuentas, cajas y dinero libre.
- Pendientes/confirmaciones.
- Deudas.
- Pagos que vienen.
- Descubrimientos.
- Nudges/recordatorios con opt-in y anti-spam.
- Email parsing solo si esta listo con confirmacion obligatoria.
- Modo discreto y privacidad visible.
- Soporte y mecanismos de correccion.

Si una feature V1 no esta lista, no se abre el lanzamiento V1 publico.

---

## 6. Construccion Interna Vs Lanzamiento

| Capa | Visible al usuario? | Objetivo |
|---|---:|---|
| Cortes internos | No | Construir Core, datos, canales, agentes, UI y politicas en orden. |
| QA interno | No | Romper flujos con datos ficticios/propios antes de exponer usuarios. |
| Release candidate V1 | No publico | Verificar que la V1 completa cumple criterios de salida. |
| Lanzamiento V1 directo | Si | Abrir Manzana como producto completo inicial. |
| Expansion post-lanzamiento | Si | Crecer por cupos, segmentos o canales sin llamarlo beta. |

Regla:

> Se puede abrir por cupos operativos, pero no se presenta como beta ni como producto incompleto.

## 7. Usuarios Objetivo Del Lanzamiento V1

El lanzamiento directo debe empezar con usuarios que puedan sentir el valor central de Manzana.

| Persona | Rol GTM | Prioridad lanzamiento | Por que |
|---|---|---|---|
| Camila | Usuario principal de habito | Alta | Registra gastos frecuentes, prueba friccion real y genera datos para descubrimientos. |
| Diego | Usuario de valor/premium futuro | Media-alta | Valida dinero libre, ingresos variables, compromisos y disposicion a pagar. |
| Valentina | Motor organico/social | Media | Valida deudas personales y entrada desde situaciones cotidianas. |

Regla:

```text
Construir el core con Camila.
Probar valor premium con Diego.
Probar lenguaje organico con Valentina.
```

## 8. Perfil Del Primer Usuario Ideal

Usuario ideal del lanzamiento inicial:

- usa WhatsApp todos los dias;
- paga con Yape, efectivo o tarjeta;
- siente que la plata se le va;
- ha intentado ordenar su dinero y abandono;
- acepta registrar movimientos reales;
- quiere claridad sin contabilidad;
- no necesita exactitud contable profesional;
- no espera integracion bancaria total desde el dia 1;
- valora privacidad, control y correccion.

Usuarios a evitar al inicio:

- negocios o equipos;
- usuarios que quieren contabilidad exacta;
- usuarios que necesitan finanzas empresariales;
- usuarios que exigen integracion bancaria directa;
- usuarios que no usan WhatsApp;
- usuarios que buscan inversiones, credito o asesoria financiera;
- usuarios que necesitan multi-moneda avanzada como requisito.

---

## 9. Posicionamiento Base

Manzana no se posiciona como:

- app de contabilidad personal;
- app de presupuestos rigidos;
- dashboard financiero;
- asistente generico de IA.

Manzana se posiciona como:

```text
Un companero financiero por WhatsApp que te ayuda a registrar, recordar y entender tu dinero sin hacer contabilidad.
```

Promesa principal:

```text
Escribe tus gastos, ingresos o deudas como hablas.
Manzana los ordena y te devuelve claridad sin juzgarte.
```

Version corta:

```text
Entiende en que se va tu plata, sin llenar una app.
```

Version WhatsApp:

```text
Tu dinero ordenado desde un mensaje.
```

Version emocional:

```text
Menos culpa. Mas claridad.
```

## 10. Canales De Lanzamiento

| Canal | Uso recomendado | Nota |
|---|---|---|
| Founder-led | Primeras conversaciones, aprendizaje cualitativo, soporte inicial. | Alto valor, bajo volumen. |
| Lista de espera | Controlar demanda y priorizar usuarios correctos. | No llamarla beta. |
| Referidos controlados | Crecer por confianza. | Activar solo si soporte y producto sostienen calidad. |
| Contenido organico | Educar sobre claridad financiera sin culpa. | Debe sonar humano, no financiero generico. |
| Comunidades | Freelancers, jovenes profesionales, usuarios de Yape/WhatsApp. | Evitar promesas exageradas. |
| Ads pagados | Solo cuando mensaje y onboarding esten probados. | No empezar por ads masivos. |

---

## 11. Landing De Lanzamiento

La landing de V1 debe tener un objetivo:

```text
Que el usuario entienda en segundos que puede ordenar su dinero desde WhatsApp.
```

Debe incluir:

1. Promesa clara.
2. WhatsApp como entrada principal.
3. Ejemplo real de mensaje.
4. Resultado visible: movimiento ordenado / dinero libre / pendiente.
5. Privacidad y control.
6. CTA de acceso a V1.

No debe incluir:

- lista enorme de features;
- dashboard como protagonista antes de WhatsApp;
- promesas de automatizacion bancaria;
- copy de asesor financiero;
- "beta" como etiqueta.

---

## 12. Primer Valor Esperado

El primer valor debe ocurrir el mismo dia.

Ejemplo:

```text
Usuario escribe: "gaste 8 cafe y 15 taxi"
Manzana responde: "Listo. Separe 2 movimientos: cafe S/8 y taxi S/15."
Dashboard refleja historial y dinero libre si hay datos suficientes.
```

Primer valor minimo:

- registrar algo por WhatsApp;
- corregir si se equivoca;
- ver historial ordenado;
- entender que nada dudoso se registra sin confirmacion;
- sentir que puede volver mañana.

---

## 13. North Star

North Star recomendada:

```text
Weekly Clarity Actions
```

Definicion:

```text
Acciones semanales donde el usuario obtiene claridad real:
movimiento confirmado, pendiente resuelto, deuda actualizada,
pregunta financiera respondida, descubrimiento util visto o pago recordado.
```

Por que funciona:

- no mide solo mensajes;
- no mide solo registros;
- incluye rutas parciales;
- conecta producto con retencion;
- evita optimizar spam;
- conecta con unit economics por outcome.

---

## 14. Metricas De Lanzamiento V1

| Area | Metrica |
|---|---|
| Activacion | % usuarios que logran primer valor D0. |
| Habito | Movimientos confirmados por usuario por semana. |
| Confianza | Correcciones completadas sin abandono. |
| Claridad | Consultas o descubrimientos vistos. |
| Retencion | D1, D7, D30. |
| Privacidad | Opt-ins, opt-outs, modo discreto usado. |
| Costos | Costo por usuario activo y por outcome. |
| Calidad IA | Clasificacion correcta, aclaraciones, errores corregidos. |
| Soporte | Casos por usuario y tiempo de resolucion. |

Targets iniciales deben definirse antes del lanzamiento publico.

---

## 15. Feedback System

El feedback no debe ser una lluvia de opiniones.

Debe capturar:

- que intento hacer el usuario;
- donde se trabo;
- que esperaba que pasara;
- si sintio alivio, control o confusion;
- si volveria a usarlo;
- que frase usaria para explicar Manzana a otra persona.

Eventos cualitativos:

- entrevista corta post-D0;
- pregunta D7;
- revision de errores frecuentes;
- feedback de soporte;
- analisis de abandono.

---

## 16. Monetizacion

Manzana no debe cobrar antes de entender:

- costo real por usuario;
- costo por usuario retenido;
- soporte necesario;
- uso de WhatsApp/IA/email;
- valor percibido por segmento.

Pero tampoco debe evitar hablar de valor.

Antes de pricing publico se necesita:

- `pricing_snapshot_v1`;
- escenarios de uso ligero/medio/intensivo;
- politicas de cancelacion/reembolso;
- terminos de pago;
- soporte definido.

---

## 17. Criterios Antes De Lanzamiento V1

- [ ] V1 completa construida segun alcance.
- [ ] Fase 6 visual reconstruida y aprobada.
- [ ] WhatsApp registro simple probado.
- [ ] Correccion simple probada.
- [ ] Dashboard muestra historial, pendientes, Mi Dinero y movimientos.
- [ ] Pendientes no afectan saldos.
- [ ] Deudas y pagos que vienen probados.
- [ ] Descubrimientos V1 definido y probado.
- [ ] Nudges/recordatorios con opt-in y anti-spam.
- [ ] Politica de privacidad publica lista.
- [ ] Terminos de servicio listos.
- [ ] Disclaimer financiero/IA visible.
- [ ] Soporte definido.
- [ ] Ruta de borrado/exportacion operativa.
- [ ] Eventos de activacion instrumentados.
- [ ] Eventos de costo basicos definidos.
- [ ] Primer mensaje aprobado.
- [ ] Mensajes de error aprobados.
- [ ] Modo discreto considerado en proactivos.
- [ ] No se prometen features fuera de V1.

---

## 18. Operacion Del Lanzamiento

Aunque sea V1 directa, el lanzamiento puede abrirse con control operativo:

- cupos limitados por capacidad de soporte;
- lista de espera si hay demanda;
- activacion por segmentos;
- monitoreo diario de errores;
- pausa temporal si hay riesgo financiero o privacidad;
- comunicacion clara si una integracion aun no esta disponible.

Esto no es beta. Es operacion responsable de una V1.

---

## 19. Criterios De Pausa

Pausar apertura de nuevos usuarios si:

- usuarios no entienden que hacer;
- IA falla en clasificaciones basicas;
- correcciones frustran;
- WhatsApp se siente spam;
- Dashboard confunde;
- Gmail genera miedo;
- hay errores de saldos;
- soporte no puede responder;
- costos crecen sin outcomes;
- hay incidente de privacidad o confianza.

---

## 20. Criterios De Aceptacion

Este documento queda aceptado si:

- elimina beta como etapa de producto;
- define lanzamiento V1 directo;
- mantiene construccion por cortes internos;
- prioriza calidad, confianza y privacidad;
- define usuarios objetivo del primer lanzamiento;
- define posicionamiento, promesa, canales y landing;
- define North Star y metricas;
- protege privacidad en marketing;
- conecta con unit economics;
- evita bajar calidad por crecer rapido;
- deja claro cuando abrir, pausar o escalar.

---

## 21. Resumen Operativo

Manzana debe lanzarse como producto de confianza, no como experimento publico.

La V1 debe encontrar el momento exacto donde el usuario piensa:

```text
Esto entiende mi forma de hablar.
Esto me ordena sin hacerme sentir mal.
Esto vale la pena volver a usarlo.
```

La regla final:

```text
Construccion interna por cortes.
Lanzamiento publico como V1 completa.
Escala solo cuando la calidad se sostiene.
```
